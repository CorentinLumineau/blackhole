## Codebase Conventions

- **Pure row builders.** Rows take the injected `config` and `BudgetPanel`. No row builder does I/O; `campaign-status.ts printLaunchSummary` is the only reader. The sibling-module precedent is `status-page-row.ts` (`statusPageRow`).
- **Row shape** (`types.ts` `LaunchRow`):
  - `header` is at most 12 characters: `Pacing`, `Autonomy`, `Resources`, `Waves`, `Other`.
  - `consequence` is at most `MAX_CONSEQUENCE_CHARS` (140, `launch-summary.ts:23`).
  - Display-only rows set `adjustable: false`. `gateCards` filters on it (`launch-summary.ts:356`), so the card count is unchanged.
- **Reuse, never re-derive (V-INT-02):**
  - `resolveBudgetSettings` and `parallelMaxOf` (`budget.ts`)
  - `resolvePaceGateThresholds` and `DEFAULT_PACE_GATE` (`scripts/lib/pace-gate.ts:26,132`)
  - `when` (exported from `budget.ts`, already imported by `launch-summary.ts:6`) and `plural` (local at `launch-summary.ts:62`; export it rather than copy it)
- **Absent vs default:** `resolveBudgetSettings` fills defaults, so an absent block is detected by raw key presence (`Object.hasOwn(config, 'usage_budget')`). The same applies to `resource_policy` and `wave_scheduling`.
- **Values never leak into Other config:** it lists key names only. Long free-text fields (`fan_out_override` is about 600 characters, `rationale`, `rule`) are never printed; rows show a presence marker or a count.
- **Coverage-check pattern:** declared doc against emitted code, both directions, the same as `PANEL_ROW_KEYS` (`status-coverage.check.ts:62-66`). The new column is appended after `Reason` because `parseCoverageTable` is positional (`cols[0..3]`).
- **Snapshot fixtures** are regenerated from the builder, never hand-edited.
- **Comments:** no issue numbers in source comments (V-DOC-06). The rationale is anchored once at `LAUNCH_ROW_CLAIMS`.

## Database/API Schema Changes

No config schema change: no key is added to `config.json`. Exported TypeScript surface:

```ts
// types.ts
export const LAUNCH_ROW_KEYS = ['scope', 'order', 'merge', 'pacing', 'budget', 'status_page', 'kaizen_staging',
  'autonomy', 'resource_policy', 'wave_scheduling', 'peers', 'sleep', 'other_config'] as const;
export type LaunchRowKey = (typeof LAUNCH_ROW_KEYS)[number];   // CATCHUP_ROW_KEYS removed (now identical)

// launch-config-rows.ts
export type RowClaim = string | { block: string; keys: readonly string[] };
export const LAUNCH_ROW_CLAIMS: Record<LaunchRowKey, readonly RowClaim[]>;
export const LAUNCH_ROW_LABELS: Record<LaunchRowKey, string>;
export function runPacingRow(config: Record<string, unknown>, budget: BudgetPanel): LaunchRow;
export function autonomyRow(config: Record<string, unknown>): LaunchRow;
export function resourcePolicyRow(config: Record<string, unknown>): LaunchRow;
export function waveSchedulingRow(config: Record<string, unknown>): LaunchRow;
export function otherConfigRow(config: Record<string, unknown>): LaunchRow;
```

Claim rule: a whole-block claim (a string) is allowed only when the row's value reads the whole block. A block the row reads only partly gets a keyed claim that lists exactly the depth-1 keys the row's value reads, so its other keys fall through to Other config. Two rows may hold keyed claims on the same block when their key sets are disjoint. A whole-block claim is exclusive.

The starting set follows. The implementer may move a key between rows only if the PR 2 table moves with it.

## Decision Record

- **Context**: the launch summary hid most of `config.json` (autonomy, resource policy, wave scheduling, pacing provenance), so the gate approved a run the owner could not see.
- **Alternatives**: easy path, a fixed list of extra rows with no claim registry, so a new config block ships unseen again. Hard path (chosen, ADR-058 Option A): rows claim blocks in code, the unclaimed remainder is listed by name, and V-CONFIG-03 cross-checks the declaration in both directions. Leaf-level claims (Option B) and a second coverage table (Option C) were rejected.
- **Choice**: Option A as a 2-PR split. PR 1 ships the claims registry with the rows that use it; PR 2 ships the blocking check.
- **Rationale**: the hard path costs about 190 more lines and one table column; it makes "no config reaches a run unseen" a build failure instead of a habit.
- **Confidence**: High on the design (three scorers agree); Medium on the 140-character consequence limit for long live values.
