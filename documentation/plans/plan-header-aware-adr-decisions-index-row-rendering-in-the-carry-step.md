# Plan - Issue #1390

## Objective
Make the `append_row` carry of `documentation/decisions/INDEX.md` render each new row in the
target file's own column schema instead of always emitting blackhole's 5-cell
`path | summary | type | status | review_trigger` row. A header whose first cell is `ADR`
(mercure `ADR | Title | Status | Date`, invest `ADR | Title | Status | Date | Traceability`)
gets `| [ADR-NNN](./file) | Title | Accepted | date |` rendered by column name. Blackhole's own
header and ambiguous headers keep today's behaviour byte-for-byte. Pareto: Gain 7 x (11 - Effort 4) = 49 (>= 30).

Root cause (V-FIX-01): `renderIndexRowLine` (`scripts/lib/check-common.ts:198-205`) is a fixed
5-cell template and `appendIndexRowIfAbsent` (`check-common.ts:282-308`) never reads the
header; `appendPipeTableRowIfAbsent` (`scripts/lib/carry-staged-artifacts.ts:196-203`) routes
the decisions index through it, with `parseIndexTableRows` (`check-common.ts:152-165`) forcing
the staged fragment into the same 5 fields on the way in.

Defects found beyond the issue text, both closed by the same ADR-aware path, so they are in scope:
1. Dedup compares `canonicalIndexPath` of the first cell. A mercure row (`ADR-001`), an invest
   row (`[ADR-001](./ADR-001-x.md)` -> `./ADR-001-x.md`) and a blackhole fragment
   (`ADR-001-x.md`) never compare equal, so a re-carry appends a duplicate row. The ADR path
   keys dedup and sort on the `ADR-\d+` token.
2. A planner-staged fragment may already be in the detected foreign schema (`planner.md` 4.8),
   e.g. 4 cells. The 5-field parse plus re-render would add a trailing empty cell. The ADR path
   parses a fragment by its own shape (blackhole 5-cell with `adr` in the type column, else
   positional `adr|title|status|date`).

Not in this plan (reported as findings): read-side parsing of the decisions index as 5-column
blackhole in `scripts/checks/adr-status.check.ts`; a 4-cell fragment appended to a blackhole-header table.

## Codebase Conventions
- Raw-line-preserving sorted insert, same technique as `insertRecordRowsSorted` and `appendIndexRowIfAbsent` (`check-common.ts:269-281`): untouched rows survive byte-for-byte; sort with a byte-order comparator, never `localeCompare` (`check-common.ts:207-213`).
- Reject embedded newlines via `assertNoEmbeddedNewline` (`check-common.ts:184`) for every rendered cell (V-INT-02: reuse, no second guard).
- Reuse `findTableBlock` for block boundaries and `parseIndexTableRows`-style `split('|').map(trim)` cell splitting.
- Comments follow the Comment Discipline rule: one canonical rationale at the definition, no issue numbers in source comments; tests may carry the issue number in test names.
- Header detection is by column name, case-insensitive, first non-separator pipe row of the table; `adr` first cell => ADR schema; anything else (including the blackhole `path` header and a missing/ambiguous header) => existing code path unchanged.

## Database/API Schema Changes
No persisted schema. Exported TS API (additive only):
- `isAdrIndexHeader(indexContent: string): boolean` — true when the table's header row's first cell equals `ADR` (case-insensitive).
- `appendAdrIndexRowIfAbsent(indexContent: string, fragment: string, opts: { today: string }): { content: string; appended: boolean }`.
- `appendPipeTableRowIfAbsent(existingContent, stagedFragment, opts?: { today?: string })` — optional third parameter; existing two-arg callers (tests lines 210-217) unchanged. Dispatch: `isAdrIndexHeader(existingContent)` ? `appendAdrIndexRowIfAbsent(...)` : existing path. `appendIndexRowIfAbsent` signature unchanged (re-exported by `doc-health.check.ts:90`).
Rendering by column name for the ADR schema: `adr` -> `[ADR-NNN](./<file>)` (file = fragment's filename cell; id from the `ADR-\d+` token), `title` -> title, `status` -> capitalised first letter, `date` -> fragment date if present else `opts.today`, any other column (e.g. `Traceability`) -> empty cell. Dedup and sort key = the `ADR-\d+` token of the first cell (rows without a token sort by their raw first cell). `date` provenance: `carryManifest` already holds `today` (line 283).

## Execution Strategy & Stop Conditions
- If a pre-existing `appendIndexRowIfAbsent` test in `check-common.test.ts` or `verify.doc-health.test.ts` changes outcome after the shared-helper extraction, stop and revert the extraction (keep the ADR path self-contained).
- If the fragment cannot be classified (neither blackhole 5-cell with `adr` type nor a row whose first cell holds an `ADR-\d+` token), then throw the existing `did not parse as a table row` error and append nothing.
- If the existing table has no `ADR` header, then the code path must be the current one; stop and revert any change that alters output for the blackhole header.
- If the change would need an edit to `renderIndexRowLine` or `parseIndexTableRows`, abort: both are shared with `doc-index-generate.ts` and out of scope.
- If the diff touches `carry-staged-artifacts.ts` outside lines 3, 190-203 and 369-372, then stop and revert that hunk (stacking contract with #1388/#1401).
