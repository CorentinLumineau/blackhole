# Plan - Issue #1380

## Objective
Apply the owner ruling of 2026-11-20 (`.blackhole/owner-decisions.json`): **fail closed**. An
unconfigured merge gate (no `merge_ready.required_checks`) returns `pending` whenever a gating check
is `SKIPPED`, and the result names the missing key `merge_ready.required_checks`. No routing-job-name
heuristic. This supersedes the earlier plan for #1380 (rule D, routing-job names), which is dropped.

**Rule (one sentence).** In `ciVerdict`, when `requiredChecks` is empty or absent and at least one
non-Vercel gating check is COMPLETED+SKIPPED, the verdict is `pending` (unless a gating check failed,
then `red` as today), `pending` lists the skipped check names, and the result carries
`missing_config: "merge_ready.required_checks"`; the CLI exits 3 and prints the same key on stderr.

**Configured behaviour is unchanged (PR #1365, bc854d11).** With a non-empty required list: each listed
check must have run and succeeded; missing/queued/SKIPPED listed checks are `pending`; a non-SUCCESS
completed conclusion is `red`; SKIPPED optional checks outside the list do not block. This repo
(`.blackhole/config.json` sets `required_checks: ["Protocol Conformance", "pr-lint"]`) therefore keeps
merging PRs with a skipped `Release Notes Gate`.

**Divergence from the issue text, stated openly.** The issue's "Expected" says an ordinary PR with
passing checks plus path-filtered skipped optional jobs stays green. The ruling overrides that for the
unconfigured case only: without the list, a path-filtered skip is indistinguishable from the #1364
gated-out shape (`ForgeCheck` is `{name,status,conclusion}` only, no job graph), so it is pending and the
owner is told which key resolves it. The "still green" expectation holds in the configured case (this
repo). Consequence to accept: a consumer repo with no list sits `pending` on any PR with a skipped job
until it sets the key; the 20 min poll cap (`merge-gate.md` § CI-wait poller contract) and the pending
message surface it, not a silent merge.

## `merge_ready.skipped_is_not_green` (F-00732): dropped
Verified `grep -rn skipped_is_not_green` over `src/`, `scripts/`, `documentation/`, `.blackhole/config.json`
finds no declaration, reader or registration anywhere (the F-00731 claim that campaign configs declare it
is false for this repo). Under the ruling the key is redundant and harmful: an opt-in `true` is already the
unconfigured default, and an opt-in key whose absence means fail-open would contradict the ruling
(V-YAGNI-01, V-KISS-01). Decision: do **not** introduce or register it; F-00732 closes as superseded by the
fail-closed default. No new config key, so V-CONFIG-02/03 gain no new row; only the existing
`merge_ready.required_checks` row's Resolution text changes.

## Database/API Schema Changes
`CiVerdict` gains an optional field: `missing_config?: 'merge_ready.required_checks'`, present only when the
fail-closed rule fired. Additive; existing consumers reading `verdict`/`failing`/`pending`/`ignored` are
unaffected (V-API-01 baseline). `CiVerdictOptions` unchanged. `unconfiguredSkipWarning` is replaced by
`unconfiguredPendingMessage(checks, options): string | null` (same signature shape, wording now states the
verdict is pending); the only importer is `scripts/ci-verdict.ts` plus its test (grep-verified at plan time;
implementer re-greps before removal).

## Threat Model
Asset: the merge gate that decides whether an autonomous squash-merge runs. Attacker: a PR author or a
misconfigured/over-eager CI workflow that gates real tests out while one cheap job passes.

| STRIDE | Threat | Severity | Mitigation | Status |
|--------|--------|----------|------------|--------|
| Spoofing | A check named like a required one (e.g. `Protocol Conformance`) emitted by another app or a commit-status `context` | Medium | Out of scope of this diff: matching is by exact name as today; branch-protection-bound required checks are the stronger control (R-ledger "merge-mode" notes). Fail-closed default does not weaken it | Accepted Risk |
| Tampering | PR modifies the workflow so every test job `if:`-skips and only `detect` passes (the #1364 shape) to get merged | High | Unconfigured: any SKIPPED gating check is `pending`, never green (this fix). Configured: the listed evidence check must have run and succeeded (#1365). Tests prove both | Mitigated |
| Tampering | PR edits `.blackhole/config.json` to empty `required_checks` and so drop to the unconfigured path | Medium | The unconfigured path is now itself fail-closed on skipped checks; wrong-typed value throws (exit 2) | Mitigated |
| Repudiation | Merge happens and nobody can see why the gate passed | Low | Verdict JSON on stdout plus stderr message name skipped checks and the missing key; pending is recorded by the orchestrator turn | Mitigated |
| Information Disclosure | Check names printed in the message leak data | Low | Check names are already PR-visible forge data; no secrets read or printed | Accepted Risk |
| Denial of Service | Fail-closed default leaves PRs `pending` forever in an unconfigured repo (availability of the merge path) | Medium | Deliberate owner-accepted trade-off; message names the one-line fix (`merge_ready.required_checks`); 20 min poll cap hands over to the retry/needs-chef path; a SKIPPED required check was already pending after #1365 | Accepted Risk |
| Elevation of Privilege | Any route that makes an unconfigured gate return green despite a SKIPPED gating check (fail-open regression, e.g. a future refactor re-adding an `executed` shortcut) | High | Red-first tests pin pending on the incident shape and on an ordinary skipped-optional shape at both library and CLI level (exit code 3, stdout `missing_config`), so the old behaviour fails them (V-TEST-11, V-UNFALSIFIABLE-01) | Mitigated |
