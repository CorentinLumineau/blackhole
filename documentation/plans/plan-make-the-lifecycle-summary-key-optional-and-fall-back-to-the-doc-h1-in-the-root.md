# Plan - Issue #1403

## Objective
Blackhole requires a sixth lifecycle key, `summary:`, and builds each root `documentation/INDEX.md` Summary cell only from it (`scripts/lib/doc-index-generate.ts:43`, empty string when absent). A doc authored under mercure's schema (no `summary`) therefore gets an empty Summary cell on regeneration and an advisory V-DOC-GOV-02 finding (`scripts/checks/doc-health.check.ts:40-43`, `ok: true`). Blackhole is also self-inconsistent: the judgment audit (`src/references/audits/27-doc-governance-judgment-audit.md:27`) already lists only five keys. Fix (blackhole side only): the generator falls back to the doc's first H1 when `summary` is absent or empty, and `summary` becomes an optional key in the check and in `doc-governance.md`. Pareto: Gain 6 x (11 - Effort 2) = 54 (>= 30).

Root cause (V-FIX-01): `summary` was made mandatory in ADR-031 Phase 1 as the single source for INDEX rows, with no fallback for docs authored under another schema; the lifecycle check and the prose rule hard-code that requirement.

Decision record: easy path = H1 fallback + `summary` optional (chosen); hard path = keep `summary` required and have the carry step backfill it (migrate script) into foreign docs. Rejected: it rewrites docs the repo does not own and keeps false V-DOC-GOV-02 findings. Cost: a doc without `summary` shows its title as its row summary (less descriptive than a hand-written line); an author who wants a better line still sets `summary`. Fallback is H1 only, no "first sentence" (a sentence heuristic over prose is non-deterministic and `|`/newline-hazardous). Confidence: High.

## Codebase Conventions
- Reuse `parseMdFrontmatter` (`scripts/lib/build/content.ts:78-82`, returns `{frontmatter, body}`) and `parseFrontmatterFields` (84-94); no new frontmatter parser (V-INT-02). Fallback is a single regex on `body`: first line matching `^#[ \t]+(.+?)[ \t]*#*[ \t]*$` (multiline), result trimmed.
- Sanitise the fallback for the table row: collapse whitespace and replace `|` with `/`, because `renderIndexRowLine` (`check-common.ts:198-205`) only rejects newlines and `parseIndexTableRows` (152-165) splits on every `|`; an unsanitised H1 containing `|` would make the committed row and the generated row disagree and trip V-DOCHEALTH-04.
- Precedence: a non-empty frontmatter `summary` always wins; `summary:` with an empty value (parsed as `''`) falls back too; no H1 -> `''` (today's behaviour, no throw).
- Fenced code containing `# ` lines before the first real H1 is an accepted edge (not parsed); the committed tree is the oracle via `generate-doc-index.ts --check`.
- Comment discipline (V-DOC-05/06): one rationale comment at `h1Fallback`; no issue numbers in source comments (test names may carry #1403).
- Tests: bun:test, fixture helpers `withFixtureDir`/`write`/`doc` already in `doc-index-generate.test.ts`; `doc()` emits `# Fixture` as its H1, so fixtures built with it get summary `Fixture`.
