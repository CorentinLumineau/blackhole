# Plan - Issue #714

## Objective
Fix `templates/hooks/pretooluse/utils/hook-event-log.js`'s `BARE_TEMP_DIRS` broad-root
classification so it survives a symlinked temp-root ancestor (macOS: `os.tmpdir()` resolves
under `/var/folders/...` while its realpath sits under `/private/var/folders/...`), without
weakening the guard `#510`/`F-00088` put in place. This closes `#510`/`#512` test failures on
macOS (`bun test` fails those two cases: expected exit 2, got 0) while adding a Linux-observable
regression test for the same defect class, since this workstation cannot run macOS directly.

## Root Cause (verified against source, not assumed)
`BARE_TEMP_DIRS` (`templates/hooks/pretooluse/utils/hook-event-log.js:123`) is built with
`path.resolve()`, which does **not** follow symlinks:
```
const BARE_TEMP_DIRS = new Set(['/tmp', '/var/tmp', os.tmpdir()].map((p) => path.resolve(p)));
```
`isAcceptableScratchpadDir` (line 125-134) then compares an incoming `scratchpad_dir`/`cwd`
value against this set via `resolved = path.resolve(value)` — also symlink-unaware — while the
file's own `resolveExistingAncestor` helper (line 95-106, already realpath-based) is defined
just above and used everywhere else in this file for exactly this kind of comparison (`isUnderRoot`,
`readAssignedWorktreeRoot`). On darwin, `os.tmpdir()` returns a path under `/var/folders/...`;
`/var` is itself a symlink to `/private/var`, so `fs.realpathSync(os.tmpdir())` yields
`/private/var/folders/...` — a different string than `path.resolve(os.tmpdir())`. A caller that
supplies the *realpath'd* form of `os.tmpdir()` (which is what `scripts/hooks-validate-file.test.ts`
does throughout, via `fs.realpathSync(os.tmpdir())`) therefore does not match any literal entry in
`BARE_TEMP_DIRS`, and `isAcceptableScratchpadDir` incorrectly returns `true` for a bare temp root.
This is the same class of gap `#510`/`F-00088` closed for `scratchpad_dir` breadth — now reopened
through a symlinked alias instead of the literal string.

Two call sites share this one broken comparison, both fixed by the same change (`V-INT-02`, no
second check written): `readScratchpadDir` (line 142-158, validating `.blackhole/config.json`'s
`scratchpad_dir`) and `validate-file-changes.js:122`'s cwd-fallback-breadth check.

**Not the root cause** (ruled out): `resolveExistingAncestor`/`isUnderRoot` themselves are already
realpath-based and correct — the bug is isolated to `BARE_TEMP_DIRS`'s construction and
`isAcceptableScratchpadDir`'s comparison, not to the worktree-containment logic that consumes
`isAcceptableScratchpadDir`'s verdict.

## Fix
In `templates/hooks/pretooluse/utils/hook-event-log.js`:
1. Build `BARE_TEMP_DIRS` with the existing `resolveExistingAncestor` helper instead of
   `path.resolve` — `resolveExistingAncestor` is already defined above this line and already used
   for every other symlink-aware comparison in the file, so this is reuse, not a new helper
   (`V-INT-02`).
2. In `isAcceptableScratchpadDir`, compare `BARE_TEMP_DIRS.has(...)` against
   `resolveExistingAncestor(value)` instead of `path.resolve(value)` — the structural checks
   above it (`path.isAbsolute`, `segments.length < 2`) stay on the raw `path.resolve(value)` form
   since they are about path shape, not filesystem identity, and do not need realpath.
3. Leave the `$HOME` comparison, `path.isAbsolute` check, and the two call sites'
   (`readScratchpadDir`, `validate-file-changes.js`) surrounding logic untouched — the fix is
   confined to the two lines that build and consult `BARE_TEMP_DIRS`. This is a strengthening
   change only: every value the guard denied before this fix is still denied after it: it only
   adds symlinked aliases of the three bare roots to the deny set, and cannot narrow it.

   ```ts
   // the check on macOS. Reproduced portably here via a fresh symlink whose target is the
   // worker's own realpath'd temp root, so the failure is observable on Linux CI too.
   test('#714: a scratchpad_dir reaching a bare temp root only through a symlinked ancestor is rejected', async () => {

     fs.symlinkSync(tmpRoot, symlinkedAlias, 'dir');
     try {
       await withLinkedWorktree(
         'blackhole-hook-714-',
         async (mainRepo, worktree) => {
           const target = path.join(worktree, 'src', 'foo.ts');

         (mainRepo) => {
           writeCampaignConfig(mainRepo, { scratchpad_dir: symlinkedAlias });
           return symlinkedAlias;
         },
       );
     } finally {
       fs.rmSync(symlinkedAlias, { force: true });
     }
   });
   ```
