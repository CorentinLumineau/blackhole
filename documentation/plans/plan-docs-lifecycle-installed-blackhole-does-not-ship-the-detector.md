# Plan - Issue #1399

## Objective
The Claude marketplace bundle ships no `.sh` script, so the planner's `scripts/detect-doc-schema.sh`
calls (`src/agents/planner.md:108`, `:396`, `:463`) cannot resolve in an installed plugin, and their
bare relative path would resolve against the consumer cwd anyway. `src/SKILL.md:75` has the same
gap for `bash scripts/detect-frontend.sh`. Root cause: `scripts/lib/build/claude-plugin-runtime.ts`
derives what to ship from prose via `INVOCATION_RE` (line 41), which only matches
`bun [run [--cwd d]] scripts/x.ts`, so `.sh` references are invisible to
`listRuntimeScriptEntrypoints` (45-54), `rewriteScriptInvocations` (86-88),
`unrewrittenInvocationErrors` (92-103) and, through the first, to `claudePluginRuntimeErrors`
(145-148, which already asserts every listed entry point ships). Fix: teach the same
invocation-derived list about `bash scripts/x.sh`, and write the planner's three call sites in that
form. Gain 7, Effort 3, Priority 56 (issue's own effort=1 estimate is low: regex, rewrite, closure
guard, tests and mirror rebuild).

The issue's suggested copy list in `build.ts`/`facts.ts` is rejected: the invocation-derived list
is already the SSOT (V-INT-02, V-DRY-01), and a second hand list would drift. The suggested
"packaging test" already exists as `claudePluginRuntimeErrors`; the gap was only that the lister
could not see `.sh`.

## Touch-Paths

Not touched: `templates/hooks/**` (so no `package.json` version bump, V-PLUGIN-01 inert),
`scripts/detect-doc-schema.sh`, `scripts/detect-doc-schema.test.ts`, `scripts/detect-frontend.sh`.
**Ordering vs #1398**: no shared source file or line (#1398 edits `scripts/detect-doc-schema.sh`
27-32 and 96-113 and its test). One build-output coupling: this change commits a byte-for-byte
copy at `plugins/blackhole-claude/scripts/detect-doc-schema.sh`. Whichever of #1398/#1399 merges
second must run `bun run build` on its branch so that mirror matches the script (the dist
sync/claude-dist checks fail otherwise). Recommended order: #1398 first (its diff is then picked up
by this PR's build), but either works.
