# Plan: issue #895 — worktree-removal-guard: detached-HEAD reachability + heredoc-body false positive

## Objective

Two loosenings to `worktree-removal-guard.js`, in one PR (router decision `R-00006`,
`task_type: bugfix`, `security_review_required: true`, size `m`):

- **Problem 1 (detached-HEAD-on-main false refusal)**: **verification only — no source-code
  defect exists on `plan_base_commit`.** `checkDetachedReachability` (added by PR #776,
  `worktree-removal-guard.js`) already resolves this exact scenario via
  `git for-each-ref --contains <sha> refs/remotes/`, and it is already pinned by two tests —
  `scripts/hooks-validate-bash.test.ts:969` (allow: reachable) and `:1011` (deny: unreachable,
  the `rv-887` case). The live refusal reported in the issue (`pattern_id:
  worktree-remove-unverifiable`, prose "is in detached HEAD state" with no reachability
  language) does not match what current source can even produce for a detached HEAD — current
  source can only emit `worktree-remove-detached-unreachable` or allow. This is the exact
  fingerprint of the **stale installed plugin cache** issue `src/references/blackhole-protocol.md`
  § "Installed plugin cache refresh (#800, ADR-030)" already documents: the installed cache at
  `~/.claude/plugins/cache/blackhole-marketplace/blackhole/0.20.0/` was last built 2026-08-30,
  five days before `checkDetachedReachability`'s fix (PR #776, merged 2026-09-03) reached
  `main`. **This plan does not modify `checkDetachedReachability` or `checkUnpushedCommits`.**
  Task 1 runs the existing tests as fresh evidence and adds one regression-locking test for
  issue #895's own reported shape; Task 5 (`package.json` version bump, forced anyway by
  Problem 2's `templates/hooks/**` touch) is the operational remedy that lets a rebuild +
  reinstall pick up the fix that already exists on `main`.
- **Problem 2 (heredoc-body false positive)**: genuine source defect. `clauseTailFrom`'s
  `$(...)`-swallowing helper (`skipDollarParenSpan`) is naive character-by-character `(`/`)`
  depth counting with no awareness of `computeMaskedSpans`'s existing heredoc-body masking, so
  when a heredoc lives inside a `$(...)` (e.g. `"$(cat <<'EOF' … EOF)"`), its entire body —
  including any literal `worktree`/`remove` words in prose — is pulled verbatim into the
  *enclosing* clause's token stream. `findRemovalInvocations`'s dynamic-executable fallback
  (`containsWorktreeRemoveTokens`) then finds that adjacent word pair inside the heredoc body
  and denies with `worktree-remove-unresolvable-path` — exactly the issue's reported repro. Fix:
  add a heredoc-body-only mask (new, additive export from `bash-context.js`, reusing its
  existing heredoc-scanning helpers verbatim) and thread it through `skipDollarParenSpan` and
  `clauseTailFrom` only. `findClauseStartIndices` (the actual quote-UNAWARE clause **splitter**
  ADR-040 protects) is untouched — it already receives and correctly consults the general
  `masked[]` array for clause-start purposes.

**Out of scope**: the third shape from #895 (`Write` denial to the harness scratchpad,
`pattern_id: outside-worktree`) is owned by **#879** (open — confirmed via `gh issue view 879`),
which tracks `hook-schemas.md`'s stale worktree-root-set enumeration after `scratchpad_dir`
joined `allWorktreeRoots()` (#853/#839). Not touched here (Task 8 records this boundary in the
PR/issue, no code).

## Threat Model

Trigger: `route.security_review_required: true` (router decision `R-00006`). This guard exists
specifically to prevent destructive `git worktree remove` / `rm -rf` on unpushed or unverified
work; **both fixes loosen it**. A false **allow** destroys work permanently; a false **refusal**
is an annoyance. Every row below is judged against that asymmetry.

| STRIDE category | Threat | Severity | Mitigation status |
|---|---|---|---|
| Spoofing | N/A — no identity/authentication boundary in a local shell-text classifier. | Low | N/A |
| Tampering | A crafted heredoc body engineered to hide a **real** `git worktree remove`/`rm -rf` invocation from detection, exploiting the new exclusion mechanism itself ("an over-broad heredoc exclusion is exactly how a real `rm -rf` hides" — router). | High | **Mitigated.** The new mask marks ONLY positions `computeMaskedSpans`'s existing, already-audited heredoc-body detection (issue #506) already treats as "described, not executed" — no new heredoc-boundary detection is written. A genuine removal invocation sitting **outside** any heredoc body — including one on a later clause of the *same* command line, after the heredoc's terminator — remains fully visible and is still detected: pinned by Task 4's AC4 fixture (`cat <<'EOF' … EOF` followed by a real `git worktree remove <path>` on the same line, must still deny). |
| Repudiation | N/A — decisions are recorded via the existing `.blackhole/hook-events/` durable event log (`readHookEvents`), unaffected by this change. | Low | N/A — pre-existing logging, unmodified. |
| Information Disclosure | N/A — the guard only inspects command text the harness already exposes to the hook; no new data surface. | Low | N/A |
| Denial of Service | Legitimate worktree removal wrongly refused — the literal subject of both problems (worktree accumulation cost measured at 25 worktrees, 14 detached, in the router's brief). | Medium | **Mitigated for Problem 2** by Task 3/4 (heredoc-mask fix + discriminating fixtures). **N/A for Problem 1** — no code defect exists to mitigate (see Objective); Task 5's version bump lets an eventual reinstall pick up the already-merged #776 fix. |
| Elevation of Privilege | A loosening (either problem) grants removal where it should not — the "false allow" half of the core asymmetry. | High | **Mitigated.** Problem 1: no behavior change at all (verification-only). Problem 2: gated by Task 4's two discriminating fixtures (the wrongly-refused-must-become-allowed case AND the adjacent must-stay-refused case) plus the unmodified F-00065 eval-bypass regression test, which together prove the splitter's quote-unawareness — the actual privilege boundary here — is preserved exactly. |

## Task Breakdown

1. **Verify Problem 1 is already fixed on `plan_base_commit` — no production code change.**
   Run `bun test scripts/hooks-validate-bash.test.ts` and confirm the two existing tests at
   `:969` ("allow: a detached HEAD reachable from a remote-tracking ref … #761") and `:1011`
   ("deny: a genuinely unreachable detached HEAD …") both pass. Add **one** new regression-lock
   test reproducing issue #895's own reported shape (a worktree whose detached HEAD is several
   commits behind the tip of a remote branch, not merely a fresh branch tip, to rule out an
   off-by-one in the `for-each-ref --contains` check) — expected to **pass on `plan_base_commit`
   with zero code changes**; label it explicitly as a regression lock, not a fix, in a test-file
   comment and in the PR description (`V-UNFALSIFIABLE-01` honesty requirement — this test cannot
   be red-before-green because there is nothing broken to fix).
   — **AC**: `bun test scripts/hooks-validate-bash.test.ts` reports 0 failures including the 3
   named tests; PR description quotes the passing run for `:969`/`:1011` plus the new test, and
   states plainly that Problem 1 required no source change.

2. **`bash-context.js`: add `computeHeredocBodyMask(command)`** — a new, additive export
   returning a `boolean[]` the same length as `command`, `true` only at heredoc-body character
   positions (both the quoted-delimiter full-body-mask case and the unquoted-delimiter
   literal-only-mask case), computed by an independent pass over the same private
   `consumeHeredoc`/`collectHeredocOperatorsOnLine`/`parseHeredocDelimiter`/`maskLiteralSpan`
   helpers `computeMaskedSpans` already uses (reused verbatim, not reimplemented). Do not change
   `computeMaskedSpans`'s own signature, return value, or any of its 3 existing call sites.
   — **AC**: new unit-style assertions (added inline in `scripts/hooks-validate-bash.test.ts`,
   this repo's existing convention has no separate `bash-context.test.ts`) confirm: (a) a
   quoted-delimiter heredoc body (`<<'EOF'`) is `true` in full; (b) an unquoted-delimiter body
   (`<<EOF`) has `false` at a nested `$(...)`/backtick/`${...}` span within it and `true`
   elsewhere in the body; (c) ordinary command text outside any heredoc is `false` throughout.

3. **`worktree-removal-guard.js`: thread `heredocMasked` through `skipDollarParenSpan` and
   `clauseTailFrom` only.** `skipDollarParenSpan` gains a `heredocMasked` parameter and skips
   (does not count toward paren depth) any position where `heredocMasked[i]` is true — closing a
   latent, separate risk where prose parentheses inside a heredoc body (e.g. the issue's own
   repro text, "(command substitution or environment-variable indirection)") could otherwise
   perturb the naive depth counter. `clauseTailFrom` blanks each `heredocMasked` character to a
   single space in its returned tail text, before the existing trailing-redirect stripping runs.
   `findRemovalInvocations`'s one call site for each function is updated to pass the array
   (computed once via `computeHeredocBodyMask(command)` alongside the existing
   `computeMaskedSpans(command)` call). `findClauseStartIndices` is **not** touched.
   — **AC**: `findRemovalInvocations`, `clauseTailFrom`, and `skipDollarParenSpan` are the only
   3 functions in this file with a diff; `findClauseStartIndices`'s own body has zero changed
   lines; `git diff --stat` for this file shows no changes outside these three functions plus
   their call sites.

4. **Red-before-green tests for Problem 2**, added to `scripts/hooks-validate-bash.test.ts`:
   - **(a) Wrongly-refused → must-allow** (discriminates on: dynamic executable position +
     heredoc-body word pair): a command shaped like `gh issue create --body "$(cat <<'EOF'\nSee
     the git worktree remove docs for details\nEOF\n)"` (minimal reduction acceptable). Must
     **deny** with `pattern_id: worktree-remove-unresolvable-path` when run against
     `plan_base_commit` (capture this failing run verbatim in the PR description — the red
     state) and **allow** after Tasks 2–3 land (green state, also captured verbatim).
   - **(b) Adjacent → must-stay-refused** (discriminates on: a real removal reachable *after* a
     heredoc terminator on the same command line — the issue's own AC "A genuine removal remains
     detected when it appears after a heredoc"): `cat <<'EOF' > /tmp/notes.txt\nunrelated
     text\nEOF\ngit worktree remove <path-of-a-dirty-or-unpushed-test-worktree>` on one command
     string. Must **deny** both before and after this diff.
   - **(c) Regression guard**: re-run the existing F-00065 test at `:2367`
     (`eval "cd <parent> && rm -rf <basename>"`) unmodified and confirm it still denies —
     cited explicitly in the PR description as the ADR-040 quote-unawareness invariant check.
   — **AC**: all of (a)/(b)/(c) pass in the final diff; (a)'s red state is pasted into the PR
