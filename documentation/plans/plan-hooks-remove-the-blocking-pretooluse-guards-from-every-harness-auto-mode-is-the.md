# Plan - Issue #1644

## Objective
Remove every blocking PreToolUse guard from every harness build; Claude Code auto mode is the gate (owner decision 2026-11-26, owner addendum maps each risk to a non-hook gate). Supersede ADR-061 and ADR-064 with ADR-065 (staged at `.blackhole/staged/1644/`). The change is too large for one reviewable PR (guard code about 5.9k lines, guard tests about 10.9k lines, about 374 tracked files mention the hooks), so it is split in two slices. Priority: gain 9, effort 6 gives 45 (>= 30).

Design note: the owner approved the design, so no blind-critic spawn and no `design-aggregate.ts` run (no fan-out allowed on this workstation); the ADR options are in ADR-065 itself.

- `claude-native-settings.ts` identifies blackhole's own entries with `isBlackholeEntry`; reuse it to strip existing blackhole PreToolUse entries from `.claude/settings.json` so the merge becomes a removal, leaving every foreign key and entry untouched (`V-INT-02`).
- Frontmatter edits on ADR-061/064 follow `doc-governance.md` § ADR Status Enum (`status: superseded` in frontmatter, INDEX status column and a supersession citation: `V-ADR-01..04`).

- Never hardcode count facts (`EXPECTED_CHECK_COUNT`, `VCODE_TABLE_ROW_COUNT`, content-gate budgets): re-derive from the live parser at implement time.

## Threat Model
| STRIDE | Threat | Severity | Mitigation status |
|---|---|---|---|
| Spoofing | A worker passes itself off as orchestrator to write state (the ADR-064 `agent_type` assumption) | Low | Mitigated: the trust grant disappears; single-writer rule plus `state-write-guard.ts` validation |
| Tampering | A bad write wipes `queue.json` or the ledger | High | Accepted (detect + recover): `state-write-guard.ts` validates only the orchestrator's own writes, so a worker's direct write is not prevented; detection is the guard's shrink/zero/shape refusal on the orchestrator's next install, recovery is the pre-mutation archive snapshot (`state-write-guard.test.ts`); prevention relies on worker prompts and auto mode |
| Repudiation | Denied calls no longer logged to hook-events | Low | Accepted Risk: ledger and PR audit trail remain |
| Information Disclosure | A worker stages a secret or sensitive file | High | Mitigated: reviewer V-SEC-03/V-SEC-11 BLOCK audits; no blackhole CI secret scan (accepted, stated in ADR-065) |
| Denial of Service | A destructive shell or git command in the shared clone | High | Mitigated: auto mode prompts on Claude Code; Accepted Risk on harnesses without auto mode (detective V-SEC-14/V-BRANCH only) |
| Elevation of Privilege | A worker writes outside its worktree | Medium | Mitigated: worktree-per-worker, V-SCOPE-02 review, CI verify; Accepted Risk for non-repo paths |

## Execution Strategy & Stop Conditions
- Slice 1 is one PR; the order is ADR and index edits, build-source removal, tests/checks removal, `bun run build`, version bump.
- If, after removing the guards, a non-guard module still imports a deleted `templates/hooks/pretooluse/utils/*` file, then stop and move that shared piece out of the deleted tree instead of deleting it.
- If `bun run build` leaves any `hooks.json` containing the string `PreToolUse` or a `validate-*.js` reference, then halt and fix the build source, never the generated file.
- If a removed check (`hooks.check.ts`) is the only reader of a fact in `facts.ts` that other checks still use, then revert that deletion and keep the fact.
- If CI `bun run verify` fails on a check that references a removed guard, then amend that check in the same PR; do not skip it with a waiver.
- If slice 1 diff exceeds one comfortable review (about 25k deleted lines is expected and is mostly deletion), then do not add feature code; split only by further deletion groups.
