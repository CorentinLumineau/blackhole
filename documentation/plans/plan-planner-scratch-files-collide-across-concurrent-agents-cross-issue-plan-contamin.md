# Plan - Issue #911

## Objective

Close the scratch-file-naming hazard `router-911` documented: two concurrently running
`planner`/`investigator` agents can independently pick the same generic scratch filename
(observed: a bare `/tmp/*.md` path) while staging artifacts through to `.blackhole/plans/` or
`.blackhole/staged/<issue>/`, letting one issue's write silently install another issue's content.
The issue body's own proposed fix (AC1: agents must remember issue-prefixed scratch filenames) is
a discipline-based control and was rejected in favor of a structural one: **compute the full
destination path first, write the heredoc body to `<that-full-destination-path>.tmp`, then
atomically `mv` it into place.** Two agents can no longer collide because their destinations are
already namespaced by issue (`.blackhole/staged/883/` vs `.blackhole/staged/909/`) — the `.tmp`
intermediates can never share a path. This is a prose-only fix: one new rule paragraph in
`src/references/blackhole-state.md` § Staging (the existing SSOT for this write mechanism), cited
— never restated — at every heredoc-based staging-write site in `src/agents/planner.md` and
`src/agents/investigator.md` (`V-DRY-01`). No code/logic changes, no new script, no new V-code.

**AC1 correction** (stated by the delegating orchestrator, verified independently below): the
issue names three agents (`planner`, `implementer`, `investigator`); it is two.
`src/agents/implementer.md` needs no change — its staging is fully scripted via
`carry-staged-artifacts.ts` / `promote-review-artifact.ts`, with no agent-authored heredoc
anywhere in that file (confirmed: `grep -c "cat <<" src/agents/implementer.md` at

## Considered and excluded: review-time content-provenance check

`router-911` flagged, without recommending, a possible review-time reviewer audit: does a staged
file's issue-number footprint match its own manifest issue? This is delegated to the planner to
weigh against `V-PARETO-03` (Priority = Gain × (11 − Effort) ≥ 30).

- **Gain: 3.** The primary fix (Tasks 1-3) already makes the *reported* failure — two agents
  colliding on a shared destination — impossible by construction. This backstop would only catch
  a narrower, different failure: an agent resolving the *wrong* destination outright (e.g. a
  copy-paste error naming issue #883's directory while holding #909's content). That failure mode
  is already partly covered by the secondary content-verification obligation this plan adds to
  § Staging (Task 1's "grep the `.tmp` file for its own issue number" step, itself an answer to
  the issue's own AC2) — a review-time audit would be a second, later checkpoint for the same
  narrow scenario, not the only one. Low marginal gain.
- **Effort: 5.** A real implementation needs: (a) a per-`target_kind`/`route` mapping from
  "content's issue-number footprint" to a checkable field (plan/analysis-note frontmatter already
  carries `issue:`, per `adr-supersession.check.ts`'s `parseFrontmatterFields`, but an
  `append_row` fragment — an INDEX row, an `ARCHITECTURE.md` bullet — carries no such frontmatter
  and would need a different footprint definition per `target_kind`); (b) a new reviewer audit
  module wired into the `V-AUTO-01`-style registry (`scripts/checks/audit-modules.check.ts`'s
  module-count fact, `REVIEWER_AUDIT_MODULE_COUNT`, would need bumping); (c) a new V-code row in
  `blackhole-vcodes.md` plus its Phase 3 severity classification. Not a one-line grep addition.
- **Priority = 3 × (11 − 5) = 18 < 30 → EXCLUDED.** Do not implement this backstop as part of
  this plan. If a future incident demonstrates the narrower wrong-target-path failure actually
  reaching a merged PR (as opposed to the collision failure this plan closes), re-open the
  Pareto computation with real incident evidence for Gain rather than the estimate above.

1. **Add the Scratch-file naming rule to blackhole-state.md § Staging**: insert the paragraph
   below into `src/references/blackhole-state.md`, directly after the existing "Gated by
   `docs_governance.enabled` / `docs_governance.write_governance`..." paragraph and before the
   `### \`.blackhole/staged/<issue>/manifest.json\`` heading (§ Staging currently spans lines
   111-263 of 339 total; budget headroom against the `src/references/*.md` class ceiling —
   `maxSectionLoc: 267`, `maxFileLoc: 606` — is ample for a ~24-line addition):

   ```markdown
   **Scratch-file naming (issue #911)**: every heredoc-authored write under this staging
   convention — including the plan file itself (`{repo_root}/.blackhole/plans/issue-N.md`) —
   computes its full destination path first, writes the heredoc body to
   `<that-full-destination-path>.tmp`, then atomically `mv`s it into place. This makes
   cross-issue scratch-file collision impossible by construction, not by agent discipline: two
   concurrently running agents each resolve a destination already namespaced by issue
   (`.blackhole/staged/883/…` vs `.blackhole/staged/909/…`, or `plans/issue-883.md` vs
   `plans/issue-909.md`) — their `.tmp` intermediates can never share a path, unlike a generic,
   unnamespaced scratch name (a bare `/tmp/scratch.md` chosen by convention rather than derived
   from the destination — the failure this replaces). The `.tmp` suffix is
   **extension-suffixed** (`foo.md.tmp`), never **extension-replaced** (`foo.tmp.md`): a replaced
   suffix still ends in `.md` and would be picked up by any wholesale `*.md` directory glob — the
   same `<file>.tmp` convention § Write protocol above already uses for `queue.json`/
   `findings-ledger.json`, reused rather than reinvented (`V-INT-03`). No partial-write hazard:
   the one consumer that globs a staged tree wholesale,
   `scripts/checks/adr-supersession.check.ts`'s `fs.readdirSync(plansDir).filter(n =>
   n.endsWith('.md'))`, never matches a `<name>.md.tmp` file, and both
   `carry-staged-artifacts.ts` and the reviewer's Staged Artifact Carry Audit resolve
   `staged_path` from `manifest.json` entries directly, never by directory glob — a stray `.tmp`
   left by a dead or interrupted agent is inert everywhere.

   **Secondary control — content verification before `mv`**: this naming rule closes the
   *collision* failure mode (two agents choosing the same destination); it does not close a
   *content* failure mode where an agent resolves the wrong destination outright (e.g. a
   copy-paste error naming issue #883's directory while holding #909's content — same symptom,
   different cause). Before every such `mv` into `.blackhole/`, grep the `.tmp` file for its own
   issue number and for the absence of any other issue's number — a stated obligation on the
   writing agent (`planner`, `investigator`), not left to individual judgment.
   ```

   returns `1`; the paragraph appears inside the `## Staging (ADR-021 D1)` section (verify with
